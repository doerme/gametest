# 角色 3D 重建与兼容性验证

验证日期：2026-11-12。环境：本机 macOS、Google Chrome headless、Node.js 20.12.2；主画面 390 × 844 CSS 像素，DPR 上限 1.5。

## 自动检查已通过

- `npm test`：十组回归通过，包含全角色与幽灵普通／首领模型、有效顶点／法线／颜色、真实体积、镜像部件朝外绕序、手杖施法原点随动画移动、预制件共享及资源释放。
- `npm run test:browser`：六套主题、真实鼠标两点施法、头顶符号、完整六关流程、小屏缩放、WebGL 上下文丢失／恢复，以及启动失败提示。
- 36 种主题／关卡组合按实际出怪时间线模拟，渲染最重快照，并计算全视野三角形保守上界。重复三次主题轮换，GPU 几何数量预热后稳定。
- 实际微信 CJS 包在无 document、window、navigator 和 DOM 构造器的 wx 环境启动。强制 WebGL 1，屏蔽 OES_standard_derivatives 与 EXT_sRGB，验证兼容实体光照、Canvas 颜色解码、两点划线命中、音效及前后台恢复，无着色器错误、无效绘制或 DOM 图像转换警告。此测试使用 Chrome 的 WebGL 实现，属于微信 API 兼容测试。
- 额外模拟缺少导数扩展，以及扩展声称可用但 PBR 片元着色器被编译器拒绝。两种条件均切换至 Lambert 材质，六套主题和缓存预制件全部恢复；未输出 invalid program 错误。
- `npm run preview:models`：生成 20 套角色／变体的旧版参考与正面、侧前方、背面截图，以及兼容材质版本；提供可旋转、播放动画的独立 HTML 页面和猫咪三个动作截图。造型来源见 `docs/character-models.md`。

## 实际微信工具观察及未验证项

通过窗口读取微信开发者工具 2.02.2609240 Stable、基础库 3.7.12 的原始报错，确认 MeshStandardMaterial 的片元着色器编译失败：GL_OES_standard_derivatives 不受支持，dFdx／dFdy 找不到重载。这解释了普通实体缺失而 Basic 材质的发光部件、阴影和界面仍显示。已据此增加扩展检测和编译失败恢复。

重新编译后，工具的可访问日志显示 Errors: 0，未再列出原来的着色器错误。但窗口点击多次返回 noWindowsAvailable，截图回读仍呈现旧帧，未能取得可确认的最新游戏画面。因此仅确认原始故障及新编译日志，不将实际微信视觉验收标为通过。服务端口仍关闭，未修改工具安全设置或用户的 project.config.json。

尚未连接手机，真机帧率、微信字体／音频及长时间稳定性仍需实测。手动验收：用微信工具编译最新构建，进入游戏逐主题检查猫咪背向玩家、角色实体完整、符号清楚、动画和施法正常；再在目标手机连续运行六关，确认稳定不低于 30 FPS，并验证前后台恢复与道具点击。
