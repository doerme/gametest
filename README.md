# 符咒学院 · Three.js 3D

原创竖屏微信小游戏。玩家逐笔描红汉字或在屏幕上画符，帮助小法师猫消除不断靠近的怪物。微信端和浏览器使用同一套 Three.js 渲染与输入逻辑。

## 开发和运行

需要 Node.js 18 或更新版本。

```bash
npm ci
npm run dev
```

浏览器打开 http://127.0.0.1:4173/ 。支持鼠标与触摸，桌面端以竖屏画面预览。开发构建通过 `window.__spellGame` 提供状态、暂停、渲染统计和销毁接口，微信正式构建不包含该调试入口。

微信开发者工具：

```bash
npm ci
npm run build
```

1. 以“小游戏”导入当前仓库目录，保留项目已有 AppID 配置。
2. 点击编译；入口 `game.js` 加载 `dist/wechat/game.js`。
3. 修改代码后重新执行 `npm run build`，再编译或生成真机预览。
4. **不再需要微信“构建 npm”**。Three.js 已由 esbuild 打入运行文件。不要手动修改 `dist/`。

`npm run dev` 会监听浏览器源码；微信包通过 `npm run build` 更新。

## 玩法

- 每局随机排列六套主题且不重复：幽光古堡、深海飞船长廊、极光企鹅酒店、恐龙乐园、天空之城、海上列车。
- 开始页默认推荐“开始汉字模式”，原画符玩法通过“经典模式”进入。两种模式的关间都点击“继续下一关”，继承玩法及当前速度。
- 开始选择页的法师猫面向玩家，在弹窗上下沿自动摆尾、张望和迈步，每6～9秒以星光跳跃切换位置，并轮换释放青白魔法弹、金色星芒和紫色闪电。演出无点击交互或新增音效，进入游戏后立即收起，切后台暂停。
- 游戏中在声音按钮左侧点击 `− 1.00× +` 调速，每次变化 `0.25×`，范围 `0.50×～2.00×`，到达边界时对应按钮禁用。倍率作用于当前模式的出怪、怪物移动和场景滚动；每局默认1倍，换关及前后台恢复时保留，重新开局恢复1倍。书写引导、反馈动画和3秒定身按真实时间运行。
- 声音与调速控件采用紧凑的顶部布局。怪物字牌避开控件、书写区、提示框和道具，保留避让顺序，沿边界平稳移动；空间恢复后缓慢回到头顶，减少来回跳位。
- 经典模式按箭头方向划线；`V / L` 照形状画。第三关解锁 `○`，第四关解锁 `Z`，第五关解锁 `M`，第六关解锁 `S`。
- 一次施法命中所有当前首符号匹配的敌人；多符号敌人需要依次消除。从第二关起仅显示当前符号及后续数量。
- 正确命中但怪物仍存活时，法杖会发射带尾迹的青白魔法弹，约 0.18 秒后在目标身上展开金色星芒和光圈，约 0.22 秒淡出。扣符号、得分和连击即时生效。
- 游戏中猫咪固定在画面下方；三维通道循环推进，敌人接近后扣除爱心。共五颗爱心，六关结束后通关。
- 连击达到 `3 / 5 / 10 / 20 / 50 / 100` 时，消灭得分倍率分别为 `1.2 / 1.5 / 2 / 2.5 / 3 / 4`。
- 每十次连击获得紫色闪电，每十五次获得血瓶。点击左侧库存使用；没有目标或爱心已满时不消耗。
- 音乐、声音开关、道具库存和关卡间的得分及生命继承沿用原规则。

## 汉字描红模式

- 开始页主按钮“开始汉字模式”进入默认玩法，六关持续采用汉字玩法，关间点击“继续下一关”。字库为2024修订版统编一年级上册写字表100字，按笔画数分为六组；每关22只怪物，组内全部汉字出现后再随机复习。
- 自动锁定最近的可见怪物。头顶显示完整汉字和 `已写/总笔画`，绿色边框标出当前目标。下方田字格中，绿色表示已写对，灰色表示待写，浅红色提示下一笔；从圆点起笔，按箭头方向书写，抬手提交一笔。
- 每笔采用宽松描红：先平滑抖动，再判断大致位置、长短、方向和主要转折，允许明显偏移、圆角、短钩缺失及轻微越界。仍需在格内起笔、按当前提示逐笔写；明显反向和大幅乱划需要重试。
- 连续前三次有效错笔保留连击，第四次起清空；所有错笔都保留确认的笔画。每成功写对一笔恢复三次保护，轻点、取消触摸、无目标及过期提交不消耗保护。界面显示剩余次数，重试时从头播放当前笔画引导。
- 写对后立即吸附成标准绿色笔画并播放命中特效和音效，正向提示保留1.2秒。完整写完一个字才消灭该怪物、加分并增加一次连击；相同汉字的其他怪物需要分别书写。
- 1倍速度下，每字预留 `3 + 2 × 笔画数` 秒作为出怪间隔基准，间隔至少为经典关卡基础间隔的两倍。同屏最多两只怪物，达到上限后暂停出怪计时。基础移速最高为经典模式的一半，并按笔画数进一步减慢，保证至少1.5倍书写预算的接近时间；场景滚动也随笔画数减速。局内倍率在此基础上调整，例如2倍将等待及接近时间缩短一半。
- 每10次连击获得的紫色闪电在汉字模式中提供3秒定身，同时暂停出怪计时，期间可以继续书写；再次使用刷新至3秒。回血规则相同。
- 切后台、取消触摸和缩放只取消未提交的笔画，已确认进度保留。支持浏览器鼠标和微信触摸，汉字图形与中线全部离线打包。

接口：`GameState.start(difficultyMode, gameMode = 'hanzi')` 默认汉字模式，经典模式使用内部标识 `'symbol'`。旧 `normal / plus-one` 参数在两种模式中分别映射到1倍／1.5倍。当前倍率统一存于 `timeScale`，`adjustSpeed(-1 | 1)` 调节一档，超出边界或不在游戏中返回 `false`；`startNextLevel()` 保留倍率。`captureHanziStroke(point, context)` 在按下时锁定目标和笔画序号，`handleHanziStroke(points, capturedContext)` 返回逐笔判定结果。

离线数据来源、版本、许可证和可复现导入步骤见 `src/hanzi/README.md`。浏览器验收增加三种屏幕尺寸、真实描红输入、完整汉字才消灭、六关流转、定身和前后台恢复；实际微信包另在无 DOM / `Path2D`、WebGL 1 环境下验证。

判定参数统一见 `src/hanzi/RecognitionPolicy.js`：两遍五点加权平滑、48点重采样，起终点容差为格宽的12%～22%，平滑后长度为参考笔画的35%～250%，平均轨迹距离上限0.14，后续轨迹可越出格子8%。主要转折按参考两侧笔段均至少20%格宽、转角至少55°判断，用户保留至少25°转向即可；短钩和笔锋可省略。原始轨迹另检查大幅偏离与反复往返，避免平滑将乱划误判成正确笔画。

## 经典模式的宽容手势

- 以实际位移区分点击和笔画，快速两点划线也能施法；界面拖动、多指干扰、系统取消及切后台不触发误施法。
- 去重、平滑并按弧长重采样到 64 点，使用几何特征与多模板距离共同评分。允许适度倾斜、抖动、不等长笔画、圆角和圆形缺口。
- 形状符咒允许从任一端起笔；圆形允许任意起点及顺逆时针。四个箭头仍按划动方向区分。
- 只有接近的候选才参考当前屏幕上怪物的首符号；明确的识别结果不会改成另一个目标，隐藏队列不会参与辅助。
- 首次有效失误保留连击；连续第二次失误清空。成功施法后恢复一次保护。轻点、过短轨迹和无敌人时的输入不消耗保护。
- 失误显示两秒的重试提示与符号示范；受伤、换关仍清空连击。

兼容接口 `recognize(points)` 返回符号。`recognizeDetailed(points, { expectedSymbols })` 额外返回置信度、候选、辅助标记和是否忽略；`GameState.handleGesture(points, context)` 返回符号。

## 三维实现

- 固定 Three.js **0.162.0**，优先创建 WebGL 2，设备不支持时使用 WebGL 1。微信不依赖浏览器 DOM 或 Phaser 适配器。
- 斜俯视透视镜头、圆润卡通模型、纯色顶点材质、柔和光照、距离雾和几何接触阴影。
- 法师猫及十八种怪物按旧版素材重建为真实几何模型（另有幽灵首领变体）。猫咪背向玩家、面朝怪物，保留橘白条纹、米色弯尖帽和紫金披风；角色的服饰、行李箱、冰晶肩甲、膜翼、灯骨等均为网格。四肢、翅膀、触手、披风、尾巴及法杖分别运动；场景由循环模块构成。
- WebGL 1 缺少 `OES_standard_derivatives` 时使用 Lambert 光照材质；设备声称支持扩展但实体着色器编译失败时也会恢复到此材质，保留角色配色及体积明暗。缺少 `EXT_sRGB` 时在界面着色器内解码 Canvas 颜色，避免依赖微信没有的 DOM 图像转换。
- 静止部件合并网格；模型实例共享几何体，离场敌人与特效复用，主题切换释放旧场景几何。DPR 上限为 1.5。
- 场景及角色没有图片贴图。运行时仅使用两个 Canvas 纹理：界面和符号图集；手势轨迹及世界特效使用几何体。
- 六套梦幻童话场景各自采用独立地面与建筑：星月古堡和彩窗、深海金属舷窗、冰晶酒店与迎宾地毯、蕨叶乐园与沙土踏石、浮岛云桥、夕阳海景列车与木地板。每套主题有三种交替的装饰模块，地面保持连续；两侧与远景展示藏书、珊瑚、行李、蛋巢、浮岛阶梯及灯塔等细节。
- 烛光、微尘、气泡、鱼影、极光、雪花、叶片、孢子、云层、风铃和海面反光使用独立环境时间，通道仍跟随当前关卡进度。动画使用固定缓冲区，不增加图片纹理或 WebGL 扩展依赖；换关同时释放场景几何和专属动画材质。每套场景的完整几何（含动画缓冲区）限制为 24,000 三角形。
- 旧 `assets/images`、旧二维/Phaser 源码仅供历史材料及工具使用，不进入微信包。既有软著材料未改写。

## 检查

```bash
npm test
npm run test:browser
npm run preview:models
```

第二项使用本机 Google Chrome，通过 Playwright 检查六套主题、真实输入、完整关卡流程、运行资源释放，以及微信 CJS 包在无 DOM / WebGL 1 环境下的启动和命中。输出截图和统计到 `output/three-qa/`。

场景验收页面为 `output/three-qa/themes/index.html`：包含六关总览、三个时间点的环境关键帧、隐藏界面的辨识度预览，以及 375×667、320×568 的截图链接；已保存本地升级前截图时额外显示前后对照。场景独立测试覆盖循环边界、长距离滚动、环境时间与行进距离分离、固定缓冲区和几何／材质释放。

第三项生成 `output/three-qa/models/index.html`，可直接用浏览器打开。包含全部 20 套角色／变体的旧版参考、正面、侧前方、背面、动画和两种材质切换；同目录保存全部对照 PNG、总览及面数统计。此页面自带参考图片，仅供美术验收，不进入游戏包。参考来源清单见 `docs/character-models.md`。

渲染预算为常规峰值不超过 200 次绘制调用、10 万三角形。目标 60 FPS，真机验收底线为稳定 30 FPS；浏览器或兼容测试不能代替微信模拟器与真机帧率验收。测试范围与限制见 `docs/3d-verification.md`。
